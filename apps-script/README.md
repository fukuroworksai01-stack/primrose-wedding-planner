# Web招待状の回答受付

招待状の3デザインは同じ `invite/rsvp-client.js` と送信先を利用します。ゲストはGoogleへのログインなしで、ページ内のフォームから回答できます。

## 保存先

Google Sheetsに、次の3シートを作成してください。回答シートの先頭行は `Code.gs` の `RSVP_HEADERS` と一致させます。

- `集計`：最新回答から出席・欠席・アレルギー・送迎の人数を数える
- `回答一覧`：回答IDごとに最新回答1行
- `回答履歴`：送信IDごとに確認済みの回答を記録

Sheetの共有は制限付きにします。招待客にSheetや作業フォルダを公開しません。

## 接続

1. 回答シートと同じGoogleアカウントでApps Scriptを作成します。
2. `Code.gs` を貼り付け、`RSVP_CONFIG.spreadsheetId` に保存先のIDを設定します。
3. タイムゾーンを `Asia/Tokyo` にします。必要な権限はGoogle Sheetsの読み書きです。コードは指定した保存先以外を操作しません。
4. Webアプリとして「実行するユーザー：自分」「アクセスできるユーザー：全員」でデプロイします。公開するのは回答の書き込み窓口のみです。OAuthトークンや回答をクライアントへ返しません。
5. デプロイの `/exec` URLを `invite/rsvp-config.js` の `endpoint` に設定します。URLパラメーターから送信先は変更できません。
6. ダミー回答を送信し、完了画面と `回答一覧`・`回答履歴`・`集計` の反映を確認してから公開します。

`eventKey` は公開されるイベント識別子で、秘密鍵ではありません。匿名で回答する仕様のため、公開窓口への迷惑送信を完全には防げません。ハニーポット・入力上限・保存件数上限は備えています。受付終了時は `closed: true` に変更し、新しいバージョンを同じデプロイへ反映します。

## 保存確認と変更

- iframeの読み込みや固定タイマーでは受付完了にしません。
- Cookieを送らない匿名の `fetch` で送信します。サーバーが保存を確認し、Google由来・今回の送信IDが一致するJSONを返した場合だけ完了表示します。
- 確認不能の場合、同じ内容・同じ送信IDで再送できます。二重登録はしません。
- 完了画面の「回答を変更する」は、同じ回答IDの最新行を更新し、変更履歴を残します。
- 「別の方の回答をする」は新しい回答IDを作成します。
- 氏名・アレルギーなどの入力値は端末のlocalStorageへ保存しません。画面を閉じた後の変更は、ふたりへ連絡してもらいます。別端末・開き直しからの再回答は別回答扱いです。
- LINE内ブラウザーなどで保存確認が届かない場合、同じ回答IDを引き継ぐ別の回答画面へ進めます。その画面は `google.script.run` の実行結果で完了を判定します。

## テスト

```sh
node --test tests/rsvp.test.cjs
```

スプレッドシートに数式を挿入されないよう、自由入力の先頭 `= + - @` は文字列化します。サーバー側でも必須項目・選択肢・文字数を検証し、同時送信はロックで直列化します。
